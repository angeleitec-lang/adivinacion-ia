# Frontend (Next.js) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Construir la app web en español con el flujo completo de lectura
(alta de usuario → datos de nacimiento → tirada de tarot → resultado con carta
astral, numerología e interpretación) y el paywall freemium con Stripe.

**Architecture:** Next.js (App Router) con TypeScript; cliente de API tipado;
estado de sesión con token JWT en cookie; componentes por pantalla. Consume la
API del backend (Plan 4).

**Tech Stack:** Next.js 15 (App Router), React 19, TypeScript, Tailwind CSS,
`@stripe/react-stripe-js`.

**Spec:** `docs/diseno-app-adivinacion.md` (secciones 2, 2.1, 7).

## Global Constraints

- Idioma del producto: español (todos los textos de UI).
- API base en env var `NEXT_PUBLIC_API_URL` (default `http://10.0.0.2:8000`).
- Sin lógica de negocio en el frontend: toda lectura viene del backend.
- El token JWT se guarda en cookie `httpOnly` (no en localStorage).

## Review Focus

1. Formulario sin hora de nacimiento opcional debe permitir enviar solo fecha
   (la hora es opcional) — Task 2.
2. Resultado con interpretación omitida (límite freemium) debe mostrar el
   paywall, no un campo vacío — Task 4.
3. Estado de carga y error de red deben tener feedback visible (no pantalla en
   blanco) — Task 2.
4. El carrusel de cartas no debe permitir elegir cartas ya repartidas — Task 3.
5. La rueda astral debe renderizar 12 casas etiquetadas sin solaparse — Task 5.
6. El corte envía solo `corte` (entero 1–77) y el flujo no avanza sin pregunta ni
   corte; el cliente nunca conoce el orden del mazo — Task 3A.
7. El corte funciona con ratón, táctil y teclado, tiene «Cortar por mí» y respeta
   `prefers-reduced-motion` — Task 3A.

### Task 3A: Pregunta y corte del mazo (requisito V1, spec §2.1)

**Files:**
- Create: `frontend/components/CutDeck.tsx`
- Create: `frontend/lib/corte.ts`
- Modify: `frontend/app/lectura/page.tsx` (insertar el paso de corte entre la
  pregunta y el envío)

**Interfaces:**
- Consumes: nada del backend (el corte es entrada del usuario).
- Produces:
  - `calcularPosicionCorte(distanciaPx: number, anchoMazoPx: number): number`
    en `lib/corte.ts`: devuelve un entero entre 1 y 77, proporcional a la
    distancia arrastrada y acotado a ese rango.
  - `CutDeck` con la prop `onCortar(k: number): void`; muestra el mazo boca abajo
    y llama a `onCortar` al soltar el arrastre o al confirmar.
- Orden del flujo: pregunta obligatoria → `CutDeck` → envío de
  `ReadingRequest.corte = k`. El botón de enviar queda deshabilitado hasta tener
  pregunta no vacía y corte hecho.

- [ ] **Step 1: Escribir el test de `calcularPosicionCorte` (falla primero)**

Casos: distancia 0 ⇒ 1; distancia igual o mayor al ancho ⇒ 77; mitad del ancho
⇒ 39 (redondeo al entero más cercano); entradas negativas ⇒ 1; ancho 0 ⇒ 1 sin
dividir por cero.

- [ ] **Step 2: Implementar `lib/corte.ts`**

Función pura, sin estado ni acceso al DOM.

- [ ] **Step 3: Implementar `CutDeck.tsx`**

Enfoque: eventos de puntero (`onPointerDown/Move/Up` con `setPointerCapture`) para
cubrir ratón y táctil con el mismo código; durante el arrastre, la parte superior
del mazo se desplaza en horizontal; al soltar se llama a `onCortar(k)`.
Alternativas obligatorias:
  - Teclado: el mazo es enfocable (`role="slider"`, `aria-valuemin=1`,
    `aria-valuemax=77`); flechas ajustan `k` y Enter confirma.
  - Botón «Cortar por mí»: elige `k` al azar en 1–77 y llama a `onCortar`.
  - `prefers-reduced-motion`: sin animación de desplazamiento; solo se actualiza
    el valor y se confirma con el botón.
Textos en español («Concéntrate en tu pregunta y corta el mazo»).

- [ ] **Step 4: Tests de componente (`@testing-library/react`)**

Un arrastre simulado llama a `onCortar` una sola vez con un valor entre 1 y 77;
«Cortar por mí» llama a `onCortar`; con el teclado, Enter confirma el valor
elegido; el botón de enviar sigue deshabilitado si falta pregunta o corte.

- [ ] **Step 5: Commit**

```bash
git add frontend/components/CutDeck.tsx frontend/lib/corte.ts frontend/app/lectura/page.tsx
git commit -m "feat: pregunta y corte del mazo por arrastre"
```

**Fuera de esta tarea (no implementar en V1):** contacto sostenido de 3 s
(modo móvil), corte en tres montones, elección de cartas desde un abanico.
